Binary Search Tree Augmentations

Augmentation

  • A balanced BST supports find, insert, delete, pred, succ in $O(\lg n)$.
  • Many problems need richer queries, but building an entirely new data structure from scratch is expensive.
  • We can augment nodes with extra information to answer new queries, while keeping $O(\lg n)$ updates!
  • The key constraint:
    The extra field in a node must be computable from the node's own data and its two children's extra fields alone, so it can be updated in $O(1)$ per node touched during any rotation or rebalancing step.

Augmentation

The Sacred Recipe (as handed down to us by CLRS)

  1. Choose an underlying data structure. (binary search tree, ✅)
  2. Determine additional information to maintain in the underlying data structure. (this is what we are calling our "augmentation")
  3. Verify that we can maintain the additional information for the basic modifying operations on the underlying data structure
    • "can we keep this data updated through inserts and deletions?"
    • Demonstrate locality (this data should be able to be derived from a node's contents and its children's augmentations)
  4. Develop new operations

Augmentation #1: Subtree Size

  • A simple example to start with: store size at each node: the number of nodes in its subtree (including itself)
  • Locality: size = 1 + left.size + right.size (null = 0)
